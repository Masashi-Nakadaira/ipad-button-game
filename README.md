# ボタンゲーム

iPad の Safari で遊べる、みんな向けのシンプルなボタンゲーム集です。短いルールと大きなボタンで、気軽に参加できます。結果は点数や記録として表示し、失敗を責めない作りを目指しています。

## 遊び方

画面の案内に従ってゲームを選び、表示された大きなボタンを押してください。画面を直接タッチして遊べます。対応する別端末のコントローラーから操作する遊び方もあります。接続・設定で難易度を「やさしい」「ふつう」「挑戦」から選べます。

開始・やり直し・一時停止からの再開では、3→2→1のカウントダウンを表示します（各数字は約1秒）。ぴったり10秒は説明音声のあとにカウントダウンし、「1」の次から計測します。音声をオフにした場合や読み上げに対応しない場合も、画面の合図で始まります。じゃんけん、しぜんクイズ、くらべてポン、おぼえてポン、ひかってポン、音が止まったら押せ、数えてポンの7ゲームは、答え合わせの表示後およそ3秒で次へ自動的に進みます。ぴったり10秒とみんなで100点は、表示されるボタンで次へ進みます。「もう一回あそぶ」を押すと、説明画面を挟まず最初の問題が始まります。ゲーム中に画面を離れると一時停止します。戻ったら「つづける」を押してください。問題の途中だった場合は同じ問題の内容を保って準備から再開し、答え合わせ中だった場合は次のお題へ進みます。いろあわせポンは連続ゲームのため、画面を離れて戻ると0点から最初の刺激をやり直します。

読み上げが止まらないときは約9秒後に画面の代替ボタンを使え、約30秒で自動的に音声を止めて画面の合図へ切り替わります。計測中は音声を流さず、実際の経過秒数ではない「おじゃま数字」が漂います。計測前の準備中に押した入力は受け付けません。

## 起動方法

### iPadに入れて、あとからオフラインで遊ぶ

iPad単体で遊ぶ場合は[公開ゲーム](https://Masashi-Nakadaira.github.io/ipad-button-game/)をSafariで開き、ホーム画面に追加します。ログインは不要です。MacとiPadは別々のネットワークでも使えます。手順は [iPad導入ガイド](docs/iPad導入.md) をご覧ください。公開版はタッチとBluetooth HIDキーボード入力に対応し、Wi-Fiコントローラー中継はローカルサーバー版で使います。

`http://<MacのIPアドレス>:8787` はWi-Fi内で試遊するためのアドレスです。HTTPSではないため、Service Workerを使ったオフライン導入には使えません（`localhost` は開発用の例外です）。ホーム画面に追加したアプリは、初回にオンラインで開き「オフラインで遊べる準備ができました」と表示されるまで待ってください。

### まず遊ぶ：このMacで起動する

1. このフォルダーで `npm ci`、`npm run build`、`npm start` を実行します。
2. 同じWi-FiにつないだiPadのSafariで、ターミナルに表示された `http://<MacのIPアドレス>:8787` を開きます。

Mac自身では `http://localhost:8787` を開けます。IPアドレスはネットワークによって変わることがあるため、iPadからつながらないときは起動ログのiPad向けアドレスを使ってください。終了するときは、起動したターミナルで `Ctrl+C` を押します。

### ほかのMac/PCで起動する

[Node.js 20.19以降、または22.12以降](https://nodejs.org/) と npm を用意し、このフォルダーで次を実行します。

```sh
npm ci
npm run build
npm start
```

サーバーはポート8787で起動し、同じWi-Fi上の端末からアクセスできます。ポートを変える場合は `PORT` 環境変数を指定します。

## 音楽

「音が止まったら押せ」では、ベートーヴェン作曲「歓喜の歌」の旋律をWeb Audioで自作演奏します。毎回異なる旋律の区切りから始め、音符を重ねて低音伴奏を加え、演奏中に無音の切れ目ができないようにしてからランダムな位置で止めます。既存の録音・演奏音源は使用していません。作品の成立情報は[ベートーヴェン・ハウスの作品ページ](https://www.beethoven.de/de/work/view/5556714292117504/Sinfonie%2BNr.%2B9%2B%28d-Moll%29%2Bop.%2B125?fromArchive=6192829114089472)を参照しました。著作権の保護期間が満了した著作物の扱いについては[文化庁の解説](https://www.bunka.go.jp/seisaku/chosakuken/seidokaisetsu/chosakukensha_fumei/)を参照してください。

## ゲーム

ホーム上部の「本日のゲーム」では、チームゲームを除くゲームから、その日の3ゲームが日付に応じて決まります。順番に遊び、各ゲーム100点、合計300点を目指します。難易度は開始時の設定が3ゲーム共通です。完走した結果だけを記録し、途中でホームへ戻ったりページを再読み込みしたりすると、その日の進行中セッションは残りません。

記録はこのブラウザーの `localStorage` に保存されます。同じ難易度の日別ベスト上位10件、記録がある直近21日分の推移、同じ難易度での前回結果との差を「これまでの記録」で確認できます。保存できない場合は画面に案内が出ます。履歴は最大500プレイ分です。日付は端末のローカル日付で扱います。収録ゲームと個別ルールは [ゲーム一覧](docs/ゲーム一覧.md) をご覧ください。

「しぜんクイズ」は、野菜や果物などの絵を赤・青の2択で見分けるゲームです。最初は大きく拡大され、各段階の絵を約2秒以上見てから、2段階で全体が見えるため、細部を確かめながら答えられます。14問から重複なしで5問出題し、正解は1問20点です。答え合わせの約3秒後に自動で次へ進みます。

## 動作確認について

このプロジェクトは iPad Safari 向けに開発しています。自動テストやMac上のChromium・WebKitによる確認は、iPad実機でのSafari確認とは異なります。iPad実機、BLE機器、ESP32物理コントローラーでの確認は未実施です。

## コントローラーについて

### 画面タッチ

画面上のボタンをタッチして遊べます。別端末や物理コントローラーがなくても試遊できます。対応するBluetoothキーボードをiPadでペアリングした場合、`1`〜`4`キー、またはスペースキーでも操作できます。

### Wi-Fiコントローラー

設定画面に表示されるアドレスを同じWi-Fi上のスマートフォンで開くと、4色ボタンのコントローラー画面が使えます。サーバーは同じWi-Fiネットワーク上の入力を受け付けます。WebSocketは `/ws?role=controller&room=main` に接続し、`{"type":"press","button":0,"eventId":"press-001","deviceId":"esp32-1"}` 形式のJSONを送信します。`button` は `0`〜`3` です。HTTP入力は `POST /api/press?room=main` で、同じJSONを `Content-Type: application/json` とともに送ります。`room` は1〜24文字の半角英数字、`_`、`-`、`eventId` と `deviceId` は1〜64文字の半角英数字と `_`、`.`、`:`、`-` を使えます。画面側は `/ws?role=display&room=main` で入力イベントを受け取ります。

付属のESP32サンプルは、4つのボタン入力をWi-FiのHTTP POSTで `/api/press` に送ります。チームゲームの判定は、表示側が入力を受け取った時点を使うため、Wi-Fiの遅延が結果に影響することがあります。サンプルはオフライン時の入力を送りません。また、送信前のキューにある入力がボタン押下から500ミリ秒を超えていた場合は破棄します。この500ミリ秒は送信前の待ち時間に対する制限で、ネットワーク全体の遅延を保証するものではありません。Arduino IDEでWi-Fi名、パスワード、サーバーのIPアドレスを設定してください。サンプルのGPIOは一般的なESP32向けの `25, 26, 27, 32` です。ESP32-C3などでは使用できるピンに合わせて変更が必要です。このサンプルはLEDを制御しません。まだコンパイル・実機テストをしていません。

### Bluetooth

Safariで任意のBluetooth GATT機器に直接接続する方式は使えません。Bluetooth設定からiPadに接続したHIDキーボード型コントローラーは、キーボード入力として使えます。`1`〜`4`キーが4つのボタンに対応し、スペースキーは1つ目のボタンとして扱われます。キーボード入力は実装済みですが、Bluetooth機器を使ったiPad実機での動作確認は未実施です。

サーバーの仕様とサンプルは [server.mjs](server.mjs) と [ESP32 Wi-Fiコントローラー](hardware/esp32_wifi_buttons.ino) を参照してください。

## GitHub Pagesへの更新

このリポジトリの `main` にpushすると、GitHub Actionsがテスト・静的ビルドを実行し、成功した `dist/` だけをPagesへ公開します。[実行結果](https://github.com/Masashi-Nakadaira/ipad-button-game/actions)を確認してください。公開パスは `/ipad-button-game/`、Service Worker・manifestのscopeも同じです。画面切替はReactの状態とクエリー文字列で行い、サーバーのSPAリライトは必要ありません。

```sh
npm ci
npm run build:pages
APP_BASE=ipad-button-game npm test
git add <変更したファイル>
git commit -m "Describe the update"
git push origin main
```

ゲーム中に自動再読み込みしません。オンラインでHomeに戻り「新しい版を使えます」から「いま更新する」を押します。更新後は準備完了を確認してください。ハッシュ付きassetを事前保存し、更新時に古いprecacheを整理します。APIやWebSocketは保存しません。GitHub Pagesが提供するキャッシュのため、新版の表示まで少し待つ場合があります。

## 保存先の移行

旧LAN URLや以前のHTTPSページの記録・設定は、新しい公開URLへ自動移行しません。ホーム画面アイコンも公開URLから追加し直し、追加後のアプリをオンラインで開いて準備完了を確認してください。旧記録が必要なら旧アプリやそのWebサイトデータを消さず残してください。記録のエクスポート・インポート機能はありません。
